# 👁️ First Reader

[English](README.md) | 日本語

> doc-kit では、このスキルはプラグインに入っています（入れ方はリポジトリのルートの README）。テストは `tests/first-reader/` にあります。
> 以下は取り込み元の README の訳です。「インストール」と「確かめる」に出てくるパスは、取り込み元のものです。
> このスキルが作る読みの記録のページは、doc-kit の見た目ではなく、自分のテンプレートの見た目のままです。

公開する前に、読み手に読んでもらう。

AI っぽい文章を見つけるスキルの多くは、文章そのものを見ます。禁止語、文の長さ、ダッシュの数です。それでは、本物の人が読み続けるかどうかは分かりません。
このスキルは、2 人の読み手があなたの下書きを 1 節ずつ読むところを模擬し、その人たちに何が起きたかを報告します。どこで興味を持ち、どこで興味を失い、どこでやめ、翌日に何を覚えていたか、です。
3 人目の読み手は流し読みだけをして、そもそも開いたかどうかを言います。
読み終えたあと、どの読み手にも続けて質問できます。このスキルが文章を書き直すことはありません。

## インストール

```bash
npx skills add https://github.com/Shubhamsaboo/awesome-llm-apps/tree/main/agent_skills/first-reader
```

[skills CLI](https://skills.sh) が、対応するコーディングエージェントにこのフォルダを入れます。エージェントのスキルのディレクトリに、このディレクトリを写しても使えます。
中身は Markdown と、標準ライブラリだけの Python です。オフラインで動き、依存は無く、手元のマシンの外へは何も送りません。

## 使い方

エージェントに下書きのファイルを指す（または下書きを貼る）とともに、誰に向けたものかを言います。

> review this, it's a launch post for backend engineers on our blog

数分後、エージェントがふつうの言葉で報告します。流し読みの人が開いたか、それぞれの読み手がどこで興味を持ち、どこでやめたか、何を覚えていたか、そしてあなたへの問いを 1 つ。
あわせて、ページを 1 枚作ります。下書きの各節の横に読み手のコメントが並び、流し読みの人の判定と、節ごとに注意がどう変わったかを示す帯が付きます。

読み終えたあとも、続けて頼めます。

- **「ask S what would have kept her past passage 4」**：S が、自分のメモから、自分の言葉で答えます。何が足りなかったかは言いますが、代わりに書くことはしません。
- **「again」**（エディタで下書きを直したあとに）：同じ読み手が、初めて読むものとして読み直します。ページには、前回の注意の帯が今回の帯の上に出るので、何が変わったかが見えます。
- **「quick read」**：流し読みの人だけが読みます。開くかどうかと、その理由が 2 文で返ります。

読み手は、最初の文であなたが言った読者層から選ばれます。
肩書きよりも、人として書くほうがうまくいきます。たとえば「評価用のハーネスを 3 つ作ったことがあり、読むのをやめる理由を探しているスタッフエンジニア」です。
読み手は、下書きの隣の `.first-reader/audience.json` に保存できます。そのフォルダでの実行は、毎回同じ人たちが読みます。

## なぜ読み手を模擬するのか

AI っぽさを見るスキルは、文章を測ります。読み手が経験することは測れません。
中身の無い文章の見分け方の研究によれば、確実に見抜く人が見ているのは、その文章が何を言い切っているかと、記憶に何を残すかです。語を数えているのではありません。
そこでこのスキルは、経験のほうを測ります。

模擬を正直に保つ決まりは 3 つです。
下書きは 1 節ずつ渡され、人が読める速さより速くは進みません。だから、4 節目でやめた読み手は、5 節目を見ていません。
記憶のテストは、読み手自身のメモから答えます。文章をもう一度見ることはありません。
そして読み手は、自分に起きたことと、何が違えば読み続けたかだけを報告します。下書きをどうするかは、すべてあなたが決めます。

## 確かめる

```bash
python3 agent_skills/evals/first-reader/test_first_reader.py
```

テストは一時的な下書きを作り、スキルの各部分を確かめます。
流し読みの表示、節を渡す仕組み（文章をディスクに書かない、読む速さを守らせる、読み手 1 人にトークン 1 つ）、記憶のクイズ、信頼の手がかり、読み手への質問、そしてページです。
ふるまいの仕様は [`agent_skills/evals/first-reader/`](../../tests/first-reader/) にあります。
`evals.json` の各プロンプトを、スキルを入れた新しいセッションで実行し、書いてある期待を確かめます。
`trigger-cases.json` は、スキルが発動すべきときと、すべきでないときの一覧です。
同じフォルダの記録（ledger）には、このスキルをどう試したかが書いてあります。1 本の本物のエッセイを 5 回続けて読ませた記録もあります。
